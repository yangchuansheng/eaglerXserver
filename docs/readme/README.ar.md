# EaglercraftX Server

شغّل خادم Minecraft يمكن للاعبين الانضمام إليه من المتصفح، مع تخزين دائم ولوحة لإدارة اللاعبين والعوالم والإضافات. تتضمن صورة Docker عميلَي EaglercraftX 1.8 / 1.12 وخادمَي Paper 1.8.8 / 1.12.2؛ اختر إصدار اللعبة عند بدء التشغيل.

## البدء السريع

### 1. إعداد المضيف

- **المضيف**: ثبّت Docker وجهّز تخزينًا دائمًا. تستخدم الأمثلة مسارات Linux. الصور المنشورة مخصصة لـ AMD64؛ تتطلب محاكاة ARM64 وتوافق المكتبات الأصلية تحققًا منفصلًا. راجع [القرار المعماري](../adr/0006-publish-linux-amd64-only.md).
- **الذاكرة**: يستخدم كل من Paper وBungee الإعداد `-Xms256M -Xmx256M`. خصص ذاكرة إضافية لـ JVM خارج الكومة، وتوليد العوالم والإضافات. لتعديل حجم الكومة، حرّر `run.sh` في مجلد التشغيل المعني.
- **EULA**: يكتب برنامج بدء التشغيل `eula=true`. اقرأ [اتفاقية Minecraft EULA](https://www.minecraft.net/en-us/eula) ووافق عليها قبل النشر.

### 2. تشغيل Paper 1.12.2

نفّذ الأوامر التالية على الخادم. استبدل `YOUR_SERVER` بعنوان IP أو نطاق يمكن للاعبين الوصول إليه، واستبدل `replace-with-a-strong-password` بكلمة مرور الإدارة.

يربط هذا المثال `/data/eagler-1.12` على المضيف بالمسار `/eaglerX-1.8-server` داخل الحاوية، ويحفظ **مجلد التشغيل كاملًا** بصورة دائمة: العوالم والإضافات والإعدادات وملفات الواجهة الأمامية. يُهيّأ المجلد الفارغ تلقائيًا عند أول استخدام. إذا كان المجلد الموجود غير مكتمل، يحتفظ بدء التشغيل بمحتواه ثم ينتهي. لترحيل ملفات تثبيت قائم، اتبع [النسخ الاحتياطي والترقية والتراجع](#النسخ-الاحتياطي-والترقية-والتراجع).

```bash
docker pull --platform linux/amd64 ghcr.io/yangchuansheng/eaglerx1.8server:2.2.5

docker run -d \
  --name eaglerx-1.12 \
  --platform linux/amd64 \
  --stop-timeout 45 \
  -p 5200:5200 \
  -p 127.0.0.1:5201:5201 \
  -v /data/eagler-1.12:/eaglerX-1.8-server \
  -e MINECRAFT_VERSION=1.12 \
  -e 'RCON_PASSWORD=replace-with-a-strong-password' \
  -e 'PUBLIC_GAME_URL=http://YOUR_SERVER:5200' \
  ghcr.io/yangchuansheng/eaglerx1.8server:2.2.5
```

### 3. فتح لوحة الإدارة والتحقق من الجاهزية

| نقطة الوصول | العنوان | الاستخدام |
|------|------|----------|
| اللعبة | `http://YOUR_SERVER:5200/` | شاركه مع اللاعبين واتبع [تعليمات الانضمام](#الانضمام-إلى-الخادم) |
| لوحة الإدارة | `http://127.0.0.1:5201/admin` | افتحها من المضيف وسجّل الدخول بكلمة المرور المحددة عند التشغيل |

قد يستغرق توليد العالم الأول بضع دقائق. يكتمل التشغيل عندما تعرض اللوحة **Paper is ready**. عند طول الانتظار أو ظهور خطأ، راجع [التشغيل واستكشاف الأخطاء](#التشغيل-واستكشاف-الأخطاء).

### الإدارة عن بُعد والمنافذ

لإدارة خادم بعيد، افتح نفق SSH من حاسوبك. استبدل `user@YOUR_SERVER` بعنوان تسجيل الدخول إلى الخادم عبر SSH:

```bash
ssh -N -L 5201:127.0.0.1:5201 user@YOUR_SERVER
```

أبقِ النفق مفتوحًا ثم انتقل إلى `http://127.0.0.1:5201/admin`. يمكنك أيضًا استخدام وكيل عكسي HTTPS يوجّه إلى `127.0.0.1:5201` على المضيف. يجب أن تتمكن نقطة الإدارة عبر VPN من تمرير الاتصال إلى عنوان الاسترجاع هذا.

| المنفذ | الغرض | نطاق الوصول |
|------|------|----------|
| 5200 | صفحة اللعبة عبر HTTP، الملفات الثابتة العامة واتصالات اللعبة عبر WebSocket | متاح للاعبين |
| 5201 | لوحة الإدارة، خدمة HTTP الاحتياطية ووكيل Dynmap | يُربط بـ `127.0.0.1` على المضيف |
| 25565 | Paper | Localhost داخل الحاوية |
| 25575 | RCON | Localhost داخل الحاوية |

### النطاقات المخصصة وHTTPS وعنوان اللعبة

اضبط `PUBLIC_GAME_URL` على **عنوان لعبة HTTP(S) الذي يستخدمه اللاعبون فعلًا**. تنشئ اللوحة منه روابط الانضمام السريع وعناوين `ws` / `wss`. عند تركه فارغًا، يُشتق عنوان HTTP من اسم مضيف اللوحة الحالي والمنفذ 5200 (`http://主机名:5200/`). حدده صراحةً عند استخدام نفق SSH أو نطاق إدارة مستقل أو منفذ لعبة مخصص.

يتطلب وصول اللعبة عبر HTTPS إعداد DNS وشهادة وتمرير HTTP وWebSocket إلى **5200**. وجّه وكيل الإدارة إلى **5201**. يُستخدم `PUBLIC_GAME_URL` لإنشاء عناوين الاتصال فقط؛ اضبط الوكيل والشهادة ضمن بيئة النشر.

### اختيار 1.8 أو تشغيل الإصدارين معًا

`2.2.5` هو رقم إصدار الصورة. يختار `MINECRAFT_VERSION=1.8` إصدار Paper 1.8.8، ويختار `1.12` إصدار Paper 1.12.2. تشغّل كل حاوية إصدار لعبة واحدًا في كل مرة وتستخدم مجلد تشغيل مستقلًا.

لتشغيل 1.8، عدّل هذه المعاملات في أمر البدء السريع:

| المعامل | تشغيل 1.8 وحده | تشغيل 1.8 مع 1.12 |
|------|-------------|---------------------|
| اسم الحاوية | `--name eaglerx-1.8` | كما في العمود السابق |
| إصدار اللعبة | `-e MINECRAFT_VERSION=1.8` | كما في العمود السابق |
| ربط مجلد التشغيل كاملًا | `-v /data/eagler-1.8:/eaglerX-1.8-server` | كما في العمود السابق |
| منفذ اللعبة | `-p 5200:5200` | `-p 5300:5200` |
| منفذ الإدارة | `-p 127.0.0.1:5201:5201` | `-p 127.0.0.1:5301:5201` |
| عنوان اللعبة العام | `http://YOUR_SERVER:5200` | `http://YOUR_SERVER:5300` |

اضبط `PUBLIC_GAME_URL` على عنوان هذه النسخة. لإدارة النسخة الثانية عن بُعد، استخدم `ssh -N -L 5301:127.0.0.1:5301 user@YOUR_SERVER` وافتح `http://127.0.0.1:5301/admin`.

## الانضمام إلى الخادم

1. افتح عنوان اللعبة أو رابط الانضمام السريع الذي يشاركه صاحب الخادم من صفحة Overview في اللوحة. تعرض قائمة اللعب الجماعي هذا الخادم مسبقًا: يستنتج العميل عنوان `ws://` أو `wss://` من عنوان الصفحة، لذلك تعمل المنافذ المخصصة والوصول عبر HTTPS دون أي إعداد. رابط الانضمام السريع يتصل مباشرة. للانضمام إلى خادم آخر، أضف عنوانه `ws://HOST:5200/` في اللعب الجماعي.
2. في الزيارة الأولى، اتبع توجيه LoginSecurity وأدخل `/register <password>`. استخدم `/login <password>` في الزيارات التالية. التسجيل مطلوب افتراضيًا، والحد الأدنى لكلمة المرور 6 محارف، ومهلة تسجيل الدخول 30 ثانية.
3. يدير LoginSecurity كلمات مرور حسابات اللاعبين. تستخدم لوحة الإدارة قيمة `RCON_PASSWORD` الخاصة بصاحب الخادم.

يوفّر SimpleHomes الأوامر `/sethome <name>` و`/home <name>` و`/homes`. ويوفّر SimpleTpa الأوامر `/tpa <player>` و`/tpaccept` و`/tpdeny`. تعتمد الصلاحيات والسلوك على إعدادات الإضافة الحالية.

## لوحة الإدارة والإضافات

### تسجيل الدخول وتطبيق التغييرات

يؤدي ضبط `RCON_PASSWORD` إلى تفعيل RCON وواجهة الإدارة البرمجية. بعد الدخول، يحتفظ المتصفح برمز إدارة في الجلسة الحالية؛ تنتهي صلاحيته بعد 8 ساعات افتراضيًا. يمحو تسجيل الخروج الرمز المحلي. الواجهة باللغة الإنجليزية افتراضيًا، وتدعم الصينية المبسطة وتتذكر اختيار اللغة لهذا الموقع.

يمكنك الدخول أثناء بدء Paper. تتاح أدوات التحكم باللعبة عندما يصبح Paper جاهزًا.

| الإجراء | وقت التطبيق |
|------|----------|
| الطقس والوقت وقواعد اللعبة وأوامر اللاعبين والقائمة البيضاء | تُرسل إلى Paper العامل؛ راجع استجابة وحدة التحكم |
| إعدادات الخادم مثل MOTD وحد اللاعبين ومسافة الرؤية وPVP | تُكتب في `server.properties` وتُطبق بعد إعادة تشغيل Paper |
| رفع الإضافات وتفعيلها وتعطيلها وحذفها | تُحفظ في المستودع وتُطبق بعد إعادة تشغيل Paper |
| إعادة تشغيل Minecraft من اللوحة | يُعاد تشغيل Paper بصورة منضبطة، ويواصل Bungee واللوحة العمل |
| الإيقاف من اللوحة أو `stop` في وحدة التحكم | ينتهي Paper، مما يبدأ إيقاف الحاوية كاملة |

يتاح Dynmap عبر وكيل `/dynmap/` في اللوحة. يستخدم بحث البنى المكوّن الأصلي cubiomes المضمّن في الصورة. تُحسب البنى ونقاط الظهور التقريبية من بذرة العالم، بينما تأتي مواقع اللاعبين من Dynmap أو بيانات حفظ اللاعبين. عند فتح Seed Map الخارجي، تُضمّن بذرة العالم في عنوان الوجهة.

### مستودعات الإضافات وبياناتها

يقع مستودع الإصدار النشط في `server-data/plugins-1.8` أو `server-data/plugins-1.12`. يحتوي المجلد `enabled/` على الحزم المفعّلة وبيانات الإضافات، ويحتوي `disabled/` على الحزم المعطّلة. يشير مسار Paper المسمى `plugins` إلى المجلد `enabled/` في المستودع النشط.

يستورد التشغيل الأول الحزم والبيانات المضمّنة. تحافظ مرات التشغيل التالية على حالة المستودع، بما فيها التعديلات اليدوية والتعطيل والحذف. يحفظ ربط مجلد التشغيل كاملًا جميع هذه البيانات بصورة دائمة.

تعرض اللوحة إصدار اللعبة النشط وأحجام الملفات وأوقات تعديلها والحالة عند التشغيل التالي وما إذا كانت إعادة التشغيل معلّقة:

- يجب أن تكون الملفات المرفوعة بصيغة JAR وتحتوي على `plugin.yml` في جذر الأرشيف. يجب أن ينتهي الاسم بـ `.jar` بأحرف صغيرة، والحد الأقصى **64 MiB**. يُرجع الاسم المكرر تعارضًا.
- بعد رفع إضافة أو تفعيلها أو تعطيلها أو حذفها، أعد التشغيل من اللوحة لتحميل المجموعة الجديدة. يبقى الكود المحمّل نشطًا إلى أن يتوقف Paper.
- يزيل حذف الإضافة ملف JAR ويحتفظ بإعداداتها وقواعد بياناتها. يمكن إعادة استخدام البيانات عند تثبيت إضافة متوافقة تستخدم المجلد نفسه.
- تُنفّذ ملفات JAR بصلاحيات عملية Paper. استخدم مصادر موثوقة، وراجع الحزم وافحصها قبل التثبيت، وخذ نسخة احتياطية.

يحدد `PERSISTENT_DATA_ROOT` جذرًا مشتركًا لمستودعات الإضافات وروابط العوالم القديمة. `SERVER_DATA_DIR` اسم بديل للتوافق. طريقة النشر الافتراضية هي ربط مجلد التشغيل كاملًا.

**يهيّئ مجلد البيانات المنفصل الفارغ مستودع الإضافات فقط.** تتطلب الروابط الرمزية للعوالم وجود العوالم المقابلة مسبقًا في جذر البيانات. تبقى العوالم الجديدة في مجلد `server-版本/` الخاص بالإصدار وتُحفظ عبر الربط الكامل.

لترحيل عوالم موجودة، أوقف الخادم وخذ نسخة احتياطية، ثم جهّز المجلدات `<level-name>` و`<level-name>_nether` و`<level-name>_the_end`. أسماؤها الافتراضية هي `world` و`world_nether` و`world_the_end`. يمكن لنقطة الدخول الرجوع لهذه الأسماء وتحتفظ بمجلدات العوالم الحقيقية الموجودة في مسارات الخادم. استخدم جذر بيانات مستقلًا لكل إصدار، وتحقق من الهدف الفعلي لكل رابط بعد التشغيل.

## النسخ الاحتياطي والترقية والتراجع

### إيقاف الخادم وأخذ نسخة احتياطية

تستخدم هذه الأوامر الحاوية والربط من البدء السريع. تتضمن النسخ العوالم وحالة اللاعبين وبيانات الإضافات والإعدادات وقواعد بيانات المصادقة وكلمة مرور الإدارة. احفظها في مجلد محدود الوصول.

```bash
docker stop -t 45 eaglerx-1.12
sudo install -d -m 700 /data/backups
sudo tar -czf "/data/backups/eagler-1.12-$(date +%Y%m%d-%H%M%S).tar.gz" \
  -C /data eagler-1.12
```

بعد النسخ الدوري، نفّذ `docker start eaglerx-1.12`. أثناء الترقية، أبقِ الحاوية القديمة متوقفة. إذا استخدمت `PERSISTENT_DATA_ROOT` خارجيًا، انسخ ذلك الجذر أيضًا؛ يحفظ tar الروابط الرمزية نفسها افتراضيًا.

عندما تتلقى نقطة الدخول إشارة توقف، تمنح Paper حتى 30 ثانية للخروج، ثم Bungee حتى 10 ثوانٍ. تتيح مهلة Docker البالغة 45 ثانية في المثال وقتًا لهذه الخطوات. راجع [سلوك إيقاف Docker](https://docs.docker.com/reference/cli/docker/container/stop/).

### تجهيز الترقية في مجلد جديد

**يُهيّأ مجلد التشغيل الكامل من الصورة عند التشغيل الأول فقط.** بعد تغيير الصورة، يواصل الربط الموجود توفير ملفات الخادم والواجهة الأمامية والخلفية المبنية على Python. تتطلب الترقية تحديث ملفات التشغيل صراحةً وترحيل الحالة الدائمة.

**الخطوة 1: الإيقاف والنسخ الاحتياطي.** احتفظ بالحاوية القديمة ومجلد التشغيل وإصدار الصورة.

**الخطوة 2: تجهيز مجلد تشغيل جديد.** انسخ القالب الكامل من الصورة المستهدفة. يستخدم المثال `2.2.5`؛ اختر اسم حاوية قالب ومجلدًا لم يُستخدما بعد:

```bash
docker pull --platform linux/amd64 ghcr.io/yangchuansheng/eaglerx1.8server:2.2.5
docker create --name eaglerx-upgrade-template --platform linux/amd64 \
  ghcr.io/yangchuansheng/eaglerx1.8server:2.2.5
sudo mkdir /data/eagler-1.12-next
sudo docker cp eaglerx-upgrade-template:/opt/eaglerX-1.8-server-image/. \
  /data/eagler-1.12-next/
docker rm eaglerx-upgrade-template
```

أبقِ حاوية القالب دون تشغيل. تدعم [docker cp](https://docs.docker.com/reference/cli/docker/container/cp/) نسخ الملفات من الحاويات المتوقفة. بعد نسخ القالب، رحّل الحالة الدائمة من المجلد القديم:

| البيانات | طريقة الترحيل |
|------|----------|
| `server-1.12/<level-name>` ومجلدا Nether وEnd | انسخ العوالم كاملة واجعل `level-name` متوافقًا مع أسماء المجلدات |
| `server-data/` | انسخ مستودع الإضافات كاملًا وملفات العلامات ومجلدات العوالم القديمة |
| ملفات Paper من الأنواع `*.properties` و`*.yml` و`*.json` | ادمج الإعدادات مع القالب الجديد واحتفظ بالمشرفين والقوائم البيضاء والحظر وذاكرة اللاعبين المؤقتة |
| إعدادات Bungee وقواعد المصادقة وذاكرة المظاهر المؤقتة | رحّل الإعدادات والقواعد كلًا على حدة؛ تحقق من الحالة المخصصة في الجذر ومجلدات الإضافات |
| ملفات الواجهة المخصصة والإضافات وخيارات البدء | ادمج التعديلات اللازمة واستخدم ملفات JAR والبرامج النصية وموارد الإدارة من الصورة المستهدفة |

تعيد نقطة الدخول إنشاء الروابط الرمزية `server/` و`web/` و`plugins` الخاصة بـ Paper. انسخ مجلدات البيانات الخارجية إلى مجلد جديد على المضيف، ثم اربطه بالحاوية الجديدة في مساره الداخلي الأصلي. أبقِ جذر البيانات القديم للحاوية القديمة. أدرج حالة الإصدارات الأخرى والعوالم المخصصة في قائمة الترحيل.

**الخطوة 3: تشغيل الحاوية الجديدة.** استخدم [أمر البدء السريع](#2-تشغيل-paper-1122) مع تغيير اسم الحاوية إلى `eaglerx-1.12-next` ومجلد المضيف إلى `/data/eagler-1.12-next` والصورة إلى الإصدار المستهدف. احتفظ بإصدار اللعبة وكلمة المرور والعنوان العام وربط المنافذ الأصلية.

**الخطوة 4: التحقق من الترحيل.** تأكد من جاهزية Paper وإمكانية دخول اللاعبين وسلامة العوالم وتحميل الإضافات وعمل القوائم البيضاء والخرائط. بعد ذلك، حدد مدة الاحتفاظ بالحاوية والصورة والنسخ القديمة.

### التراجع والاستعادة

إذا احتفظت بالحاوية والمجلد القديمين، أوقف الحاوية الجديدة وشغّل القديمة:

```bash
docker stop -t 45 eaglerx-1.12-next
docker start eaglerx-1.12
```

يعيد التراجع الحالة المحفوظة في المجلد القديم. احتفظ بالبيانات التي أُنشئت أثناء تشغيل الحاوية الجديدة لإمكان استعادتها لاحقًا. لاستعادة أرشيف مضغوط، استخرجه إلى مجلد جديد، واربط مجلد `eagler-1.12` المستخرج بوصفه مجلد التشغيل الكامل، واستخدم إصدار الصورة وخيارات البدء المطابقة للنسخة.

## التشغيل واستكشاف الأخطاء

تستخدم هذه الأوامر اسم الحاوية الافتراضي:

```bash
# Container health and entrypoint / HTTP logs
docker inspect --format '{{.State.Status}} / {{.State.Health.Status}}' eaglerx-1.12
docker logs --tail 100 eaglerx-1.12

# Paper console output in the managed tmux session
docker exec -e TMUX_TMPDIR=/tmp/eaglerx-tmux eaglerx-1.12 \
  tmux capture-pane -p -t mcserver:0.1 -S -100

# Public status probe when RCON is enabled, via the host or SSH tunnel
curl -sS http://127.0.0.1:5201/api/status
```

يعمل Paper وBungee داخل tmux. تستخدم وحدة Paper أعلاه الجزء الافتراضي `mcserver:0.1`، ويستخدم Bungee الجزء `mcserver:0.0`. يفحص Docker المنافذ 5200 و5201 و25565. تفحص اللوحة RCON أيضًا لتحديد جاهزية Paper.

| العارض | ما ينبغي التحقق منه |
|------|------------|
| تنتهي الحاوية فورًا | تحقق من أن `MINECRAFT_VERSION` يساوي `1.8` أو `1.12`، ثم راجع الخطأ المحدد في السجلات |
| يفيد البدء بأن مجلد التشغيل غير مكتمل | هيّئ مجلدًا فارغًا أو استعد نسخة كاملة، واحتفظ بالمجلد الحالي للتحليل |
| تفتح اللوحة بينما لا يزال Paper يبدأ | راجع تقدم توليد العالم وتحميل الإضافات في وحدة التحكم؛ تُحدّث اللوحة تلقائيًا عند جاهزية Paper |
| لوحة الإدارة البعيدة غير متاحة | تحقق من وصول نفق SSH أو وكيل الإدارة إلى `127.0.0.1:5201` على المضيف |
| رابط الانضمام خاطئ أو اتصال HTTPS يفشل | راجع `PUBLIC_GAME_URL` والمنفذ العام وتمرير WebSocket في وكيل اللعبة |
| يعيد `/api/status` الرمز 404 | اضبط `RCON_PASSWORD` وأعد إنشاء الحاوية؛ يفعّل برنامج البدء RCON باستخدام هذا الإعداد |
| يعيد الدخول الرمز 429 | تؤدي خمس محاولات فاشلة من مصدر واحد ضمن نافذة الإخفاق إلى قفل لمدة 10 دقائق؛ قد يشترك المديرون خلف نفق أو وكيل في المصدر |
| حُفظت التغييرات وبقي السلوك السابق | أعد تشغيل Paper من اللوحة بصورة منضبطة ثم تحقق من الحالة الفعلية |
| يعيد Dynmap الرمز 502 | تحقق من تفعيله واكتمال تحميله، ثم عنوان الاستماع HTTP ومنفذه |
| يفشل البحث عن البنى بالمكتبة الأصلية | راجع بيئة `linux/amd64` وأخطاء تحميل المكتبات الأصلية وقراءة بذرة العالم |

تبدأ نقطة الدخول Bungee ثم Paper ثم HTTP وتراقبها باستمرار. إذا انتهت خدمة أساسية، توقف الحاوية كاملة وتعيد حالة فشل. عند تلقي `SIGTERM` / `SIGINT` تنفّذ إيقافًا منظمًا. اضبط سياسة إعادة التشغيل مع مراعاة أن الإيقاف من اللوحة ينهي الحاوية أيضًا.

## متغيرات البيئة

مرّرها باستخدام `docker run -e`. لتغيير متغيرات الحاوية، أعد إنشاءها باستخدام الربط الحالي.

| المتغير | الافتراضي | الوصف |
|------|--------|------|
| `MINECRAFT_VERSION` | مطلوب | يختار `1.8` إصدار Paper 1.8.8، ويختار `1.12` إصدار Paper 1.12.2 |
| `RCON_PASSWORD` | فارغ | يفعّل RCON وواجهة الإدارة عند ضبطه؛ تتوقف نقاط الإدارة المحمية بالمصادقة عند تركه فارغًا |
| `PUBLIC_GAME_URL` | فارغ | عنوان لعبة HTTP(S) العام المستخدم لإنشاء روابط الانضمام وعناوين WebSocket |
| `PERSISTENT_DATA_ROOT` | `${APP_DIR}/server-data` | جذر مستودعات الإضافات وروابط العوالم القديمة؛ يهيّئ المجلد الفارغ المستودع تلقائيًا |
| `SERVER_DATA_DIR` | فارغ | اسم بديل للتوافق مع `PERSISTENT_DATA_ROOT`؛ تُقدّم القيمة الصريحة للمتغير الأخير |
| `ADMIN_AUTH_TOKEN_TTL` | `28800` | مدة صلاحية رمز الإدارة بالثواني |
| `ADMIN_AUTH_SECRET` | مشتق من كلمة مرور RCON | سر اختياري لتوقيع الرموز |
| `DYNMAP_HOST` / `DYNMAP_PORT` | `127.0.0.1` / `8123` | عنوان Dynmap الخلفي الذي تستخدمه خدمة الإدارة |

## واجهة الإدارة البرمجية

للتكامل مع البرامج النصية. تستخدم جميع النقاط منفذ الإدارة **5201**. تغطي اللوحة العمليات اليومية.

<details>
<summary>النقاط البرمجية والمصادقة وأمثلة curl</summary>

تصف كلمة «عام» متطلبات المصادقة للنقطة نفسها. ادخل إلى منفذ الإدارة عبر [نفق SSH أو وكيل إدارة](#الإدارة-عن-بُعد-والمنافذ).

| النقطة البرمجية | متطلبات الوصول |
|------|----------|
| `GET /api/connection-info` | متاحة دائمًا؛ تعيد إعدادات الدخول العام للعبة |
| `GET /api/status` | متاحة عند تفعيل RCON؛ تعيد حالة Paper والمعلومات المرتبطة |
| `POST /api/login` | تستبدل كلمة مرور الإدارة برمز عند تفعيل RCON |
| نقاط إدارة JSON مثل `POST /api/rcon` و`/api/config` و`/api/system` و`/api/plugins` | يجب أن يتضمن جسم الطلب `token` صالحًا |
| `POST /api/plugins/upload` | `Authorization: Bearer <token>` وجسم طلب JAR خام والترويسة `X-Plugin-Filename` |
| `GET /dynmap/` | وكيل مباشر إلى Dynmap؛ يحمي اتصال الإدارة الوصول |

الحد الأقصى لجسم طلب JSON هو 64 KiB، ومهلة القراءة 10 ثوانٍ. حد رفع JAR الخام هو 64 MiB، والمهلة الإجمالية للقراءة 30 ثانية. قد يشترك المديرون الذين يستخدمون مصدر نفق أو وكيل عكسي واحد في نافذة قفل الدخول نفسها.

```bash
# Exchange the management password for a token
curl -sS http://127.0.0.1:5201/api/login \
  -H 'Content-Type: application/json' \
  -d '{"password":"replace-with-a-strong-password"}'

# Use the returned token for a management command
curl -sS http://127.0.0.1:5201/api/rcon \
  -H 'Content-Type: application/json' \
  -d '{"command":"list","token":"TOKEN_FROM_LOGIN"}'
```

## التطوير والبناء والنشر

### التعديلات المحلية والتحقق

نفّذ الأوامر من جذر المستودع بعد تثبيت Python 3 وDocker. عدّل موارد الإدارة في `web-1.8/`، ثم شغّل برنامج المزامنة لتحديث `web-1.12/`. راجع [قرار صورة التشغيل الأساسية](../adr/0007-retain-the-verified-runtime-base.md) لمتطلبات الصورة والمكتبات الأصلية.

```bash
python3 script/sync_admin_assets.py
python3 script/sync_admin_assets.py --check
docker build --platform linux/amd64 -t eaglerx-local:dev .
```

يتطلب فحص الإصدار المحلي Node.js وtmux و`agent-browser` وتثبيت Chrome صالحًا للعمل. تستخدم CI الإصدار المثبت `agent-browser@0.26.0`؛ خطوات التثبيت في [سير عمل النشر](../../.github/workflows/release.yml).

```bash
agent-browser doctor
./script/release_gate.sh --evidence-dir artifacts/release-gate
```

تغطي الفحوص المحلية صياغة Python واختبارات التراجع للخادم والإضافات وموارد الإصدارين وموارد الإدارة وتدفقات المتصفح بالإنجليزية والصينية المبسطة. تستخدم فحوص المتصفح Mock Admin API محلية. يبني التحقق الكامل الصورة ويشغّل إصدارَي Paper أيضًا:

```bash
./script/release_gate.sh \
  --build --live \
  --image eaglerx-release-gate:local \
  --evidence-dir artifacts/release-gate
```

يضبط الفحص `release_ready` إلى `true` في `summary.json` فقط بعد نجاح جميع اختبارات `--live`. راجع [توثيق فحص الإصدار](../release-gate.md) لنطاق الاختبارات وصيغ الأدلة وأذونات الربط المؤقت في Linux.

### نشر إصدار

تستخدم الإصدارات الرسمية وسوم Git من الشكل `vMAJOR.MINOR` أو `vMAJOR.MINOR.PATCH`. يفحص سير العمل صورة واحدة بالكامل ثم ينشرها إلى GHCR بوسوم الإصدار وSHA للالتزام وإثبات مصدر البناء. يحدّث النشر التلقائي لأعلى إصدار الوسم `latest`. تحدّث الإعادات اليدوية الإصدار المحدد ووسوم SHA فقط.

```bash
gh workflow run release.yml -f release_tag=v2.2.5
```

يغلّف `build.sh` عمليات البناء المحلية؛ يدفع المعامل `push` الصورة مباشرة. يتبع التوزيع الرسمي [متطلب الفحص الحي الكامل](../adr/0005-require-the-live-release-gate.md) وسير عمل الوسوم أعلاه.

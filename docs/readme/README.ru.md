# EaglercraftX Server

Запустите сервер Minecraft, к которому игроки подключаются из браузера, с постоянным хранилищем и панелью управления игроками, мирами и плагинами. Образ Docker включает клиенты EaglercraftX 1.8 / 1.12 и серверы Paper 1.8.8 / 1.12.2; версия игры выбирается при запуске.

## Возможности

| Возможность | Описание |
|------|------|
| Управление сервером | Готовность Paper, игроки онлайн, тики в секунду (TPS), погода, время, игровые правила, настройки и управляемый перезапуск |
| Игроки и миры | Права оператора (OP), белые списки, исключение игроков, блокировки, телепортация, команды предметов, сохранение и границы мира |
| Управление плагинами | Отдельные репозитории для версий игры; загрузка, включение, отключение и удаление с применением после перезапуска Paper |
| Карты и сиды | Встроенный Dynmap, позиции игроков, нативный поиск структур и ссылки на внешний Seed Map |
| Встроенные плагины | LoginSecurity, SimpleHomes, SimpleTpa, WorldEdit, Dynmap |

## Быстрый запуск

### 1. Подготовьте хост

- **Хост**: Установите Docker и подготовьте постоянное хранилище. В примерах используются пути Linux. Публикуемые образы предназначены для AMD64; эмуляция на ARM64 и совместимость нативных библиотек требуют отдельной проверки. См. [архитектурное решение](../adr/0006-publish-linux-amd64-only.md).
- **Память**: Paper и Bungee используют по `-Xms256M -Xmx256M`. Оставьте дополнительную память для JVM вне кучи, генерации мира и плагинов. Размер кучи меняется в `run.sh` соответствующего рабочего каталога.
- **EULA**: Скрипт запуска записывает `eula=true`. Перед развёртыванием прочитайте и примите [Minecraft EULA](https://www.minecraft.net/en-us/eula).

### 2. Запустите Paper 1.12.2

Выполните команды на сервере. Замените `YOUR_SERVER` на IP-адрес или домен, доступный игрокам, а `replace-with-a-strong-password` — на пароль администратора.

Пример подключает `/data/eagler-1.12` на хосте к `/eaglerX-1.8-server` внутри контейнера и сохраняет **весь рабочий каталог**: миры, плагины, настройки и файлы фронтенда. Пустой каталог автоматически заполняется при первом использовании. Если существующий каталог неполон, запуск сохраняет его содержимое и завершается. Для переноса файлов существующей установки следуйте разделу [Резервное копирование, обновление и откат](#резервное-копирование-обновление-и-откат).

```bash
docker pull --platform linux/amd64 ghcr.io/yangchuansheng/eaglerx1.8server:2.2.5

docker run -d \
  --name eaglerx-1.12 \
  --platform linux/amd64 \
  --stop-timeout 45 \
  -p 5200:5200 \
  -p 127.0.0.1:5201:5201 \
  -v /data/eagler-1.12:/eaglerX-1.8-server \
  -e MINECRAFT_VERSION=1.12 \
  -e 'RCON_PASSWORD=replace-with-a-strong-password' \
  -e 'PUBLIC_GAME_URL=http://YOUR_SERVER:5200' \
  ghcr.io/yangchuansheng/eaglerx1.8server:2.2.5
```

### 3. Откройте панель и проверьте готовность

| Назначение | Адрес | Использование |
|------|------|----------|
| Игра | `http://YOUR_SERVER:5200/` | Передайте игрокам и следуйте [инструкции подключения](#подключение-к-серверу) |
| Панель управления | `http://127.0.0.1:5201/admin` | Откройте на хосте и войдите с паролем, заданным при запуске |

Первая генерация мира может занять несколько минут. Запуск завершён, когда панель показывает **Paper is ready**. При долгом ожидании или ошибке см. [Эксплуатация и устранение неполадок](#эксплуатация-и-устранение-неполадок).

### Удалённое управление и порты

Для управления удалённым сервером откройте SSH-туннель на своём компьютере. Замените `user@YOUR_SERVER` на адрес входа по SSH:

```bash
ssh -N -L 5201:127.0.0.1:5201 user@YOUR_SERVER
```

Оставьте туннель открытым и перейдите на `http://127.0.0.1:5201/admin`. Также можно использовать обратный прокси HTTPS, направленный на `127.0.0.1:5201` хоста. Доступ через VPN должен обеспечивать перенаправление трафика на этот loopback-адрес.

| Порт | Назначение | Доступ |
|------|------|----------|
| 5200 | HTTP-страница игры, общедоступные статические файлы и игровые соединения WebSocket | Открыть для игроков |
| 5201 | Панель управления, резервный HTTP-сервис и прокси Dynmap | Привязать к `127.0.0.1` на хосте |
| 25565 | Paper | Localhost внутри контейнера |
| 25575 | RCON | Localhost внутри контейнера |

### Свои домены, HTTPS и URL игры

Задайте в `PUBLIC_GAME_URL` **HTTP(S)-адрес игры, которым действительно пользуются игроки**. Панель создаёт на его основе ссылки быстрого входа и адреса `ws` / `wss`. Если значение пустое, HTTP-адрес формируется из текущего имени хоста панели и порта 5200 (`http://主机名:5200/`). Указывайте его явно при SSH-туннеле, отдельном домене управления или нестандартном игровом порте.

Игровой вход по HTTPS требует DNS, сертификата и перенаправления HTTP и WebSocket на **5200**. Прокси управления направьте на **5201**. `PUBLIC_GAME_URL` используется только для формирования адресов; прокси и сертификат настраиваются при развёртывании.

### Выбор 1.8 или запуск обеих версий

`2.2.5` — версия выпуска образа. `MINECRAFT_VERSION=1.8` выбирает Paper 1.8.8, а `1.12` — Paper 1.12.2. Каждый контейнер одновременно запускает одну версию игры и использует собственный рабочий каталог.

Для запуска 1.8 измените следующие параметры команды быстрого запуска:

| Параметр | Только 1.8 | 1.8 вместе с 1.12 |
|------|-------------|---------------------|
| Имя контейнера | `--name eaglerx-1.8` | Как слева |
| Версия игры | `-e MINECRAFT_VERSION=1.8` | Как слева |
| Подключение полного каталога | `-v /data/eagler-1.8:/eaglerX-1.8-server` | Как слева |
| Игровой порт | `-p 5200:5200` | `-p 5300:5200` |
| Порт управления | `-p 127.0.0.1:5201:5201` | `-p 127.0.0.1:5301:5201` |
| Общедоступный URL игры | `http://YOUR_SERVER:5200` | `http://YOUR_SERVER:5300` |

Задайте в `PUBLIC_GAME_URL` адрес этого экземпляра. Для удалённого управления вторым экземпляром используйте `ssh -N -L 5301:127.0.0.1:5301 user@YOUR_SERVER` и откройте `http://127.0.0.1:5301/admin`.

## Подключение к серверу

1. Откройте адрес игры или ссылку быстрого входа, которую владелец сервера передаст со страницы Overview панели. Этот сервер уже есть в списке многопользовательского режима: клиент выводит адрес `ws://` или `wss://` из URL страницы, поэтому нестандартные порты и HTTPS-доступ работают без настройки. Ссылка быстрого входа подключает напрямую. Чтобы зайти на другой сервер, добавьте его адрес `ws://HOST:5200/` в многопользовательском режиме.
2. При первом входе выполните подсказку LoginSecurity и введите `/register <password>`. При следующих входах используйте `/login <password>`. По умолчанию регистрация обязательна, пароль должен содержать минимум 6 символов, а на вход отводится 30 секунд.
3. LoginSecurity управляет паролями аккаунтов игроков. Панель использует `RCON_PASSWORD` владельца сервера.

SimpleHomes предоставляет `/sethome <name>`, `/home <name>` и `/homes`. SimpleTpa предоставляет `/tpa <player>`, `/tpaccept` и `/tpdeny`. Права и поведение определяются текущими настройками плагина.

## Панель управления и плагины

### Вход и применение изменений

Установка `RCON_PASSWORD` включает RCON и API управления. После входа браузер хранит токен администратора в текущем сеансе; по умолчанию он действует 8 часов. Выход удаляет локальный токен. Интерфейс по умолчанию английский, поддерживает упрощённый китайский и запоминает язык для текущего сайта.

Войти можно во время запуска Paper. Игровые действия станут доступны после его готовности.

| Действие | Когда применяется |
|------|----------|
| Погода, время, правила, команды игроков и белого списка | Отправляются работающему Paper; проверьте ответ консоли |
| Настройки сервера: MOTD, лимит игроков, дальность обзора и PVP | Записываются в `server.properties` и применяются после перезапуска Paper |
| Загрузка, включение, отключение и удаление плагинов | Сохраняются в репозитории и применяются после перезапуска Paper |
| Перезапуск Minecraft через панель | Управляемый перезапуск Paper; Bungee и панель продолжают работать |
| Выключение через панель или `stop` в консоли | Paper завершается и запускает остановку всего контейнера |

Dynmap доступен через прокси `/dynmap/` панели. Нативный поиск структур использует компонент cubiomes из образа. Структуры и приблизительные точки появления рассчитываются по сиду мира; позиции игроков берутся из Dynmap или файлов сохранения. При открытии внешнего Seed Map сид включается в адрес сайта.

### Репозитории и данные плагинов

Репозиторий активной версии находится в `server-data/plugins-1.8` или `server-data/plugins-1.12`. Каталог `enabled/` содержит включённые пакеты и данные плагинов, `disabled/` — отключённые пакеты. Путь `plugins` Paper указывает на каталог `enabled/` активного репозитория.

Первый запуск импортирует встроенные пакеты и данные. Последующие запуски сохраняют текущее состояние репозитория, включая ручные изменения, отключения и удаления. Подключение полного рабочего каталога сохраняет все эти данные постоянно.

Панель показывает активную версию игры, размеры и время изменения файлов, состояние при следующем запуске и наличие ожидающего перезапуска:

- Загружаемый файл должен быть JAR с `plugin.yml` в корне архива. Имя должно оканчиваться строчным `.jar`; предел размера — **64 MiB**. Совпадение имени вызывает конфликт.
- После загрузки, включения, отключения или удаления плагина выполните перезапуск через панель для загрузки нового набора. Уже загруженный код остаётся активным до остановки Paper.
- Удаление плагина убирает JAR и сохраняет настройки и базы данных. Повторная установка совместимого плагина с тем же каталогом позволяет использовать прежние данные.
- JAR выполняются с правами процесса Paper. Используйте доверенные источники, проверяйте и сканируйте пакеты перед установкой и создавайте резервную копию.

Их имена по умолчанию — `world`, `world_nether` и `world_the_end`. Точка входа может использовать эти резервные имена и сохраняет реальные каталоги миров, уже находящиеся по серверным путям. ## Резервное копирование, обновление и откат

### Остановите сервер и создайте копию

Команды используют контейнер и подключённый каталог из быстрого запуска. Копия содержит миры, состояние игроков, данные плагинов, настройки, базы аутентификации и пароль администратора. Храните её в каталоге с ограниченным доступом.

```bash
docker stop -t 45 eaglerx-1.12
sudo install -d -m 700 /data/backups
sudo tar -czf "/data/backups/eagler-1.12-$(date +%Y%m%d-%H%M%S).tar.gz" \
  -C /data eagler-1.12
```

После обычного копирования выполните `docker start eaglerx-1.12`. При обновлении старый контейнер остаётся остановленным. Если используется внешний `PERSISTENT_DATA_ROOT`, скопируйте и этот корень; tar по умолчанию сохраняет сами символические ссылки.

Получив сигнал остановки, точка входа даёт Paper до 30 секунд на завершение, затем Bungee до 10 секунд. Тайм-аут Docker в 45 секунд из примера оставляет время для этой последовательности. См. [поведение остановки Docker](https://docs.docker.com/reference/cli/docker/container/stop/).

### Подготовьте обновление в новом каталоге

**Полный рабочий каталог инициализируется из образа только при первом запуске.** После смены образа существующее подключение продолжает предоставлять файлы сервера, фронтенда и Python-бэкенда. Для обновления требуется явно заменить рабочие файлы и перенести постоянное состояние.

**Шаг 1: Остановите сервер и создайте копию.** Сохраните прежний контейнер, рабочий каталог и версию образа.

**Шаг 2: Подготовьте новый рабочий каталог.** Скопируйте полный шаблон из целевого образа. Пример использует `2.2.5`; выберите свободные имя контейнера-шаблона и каталог:

```bash
docker pull --platform linux/amd64 ghcr.io/yangchuansheng/eaglerx1.8server:2.2.5
docker create --name eaglerx-upgrade-template --platform linux/amd64 \
  ghcr.io/yangchuansheng/eaglerx1.8server:2.2.5
sudo mkdir /data/eagler-1.12-next
sudo docker cp eaglerx-upgrade-template:/opt/eaglerX-1.8-server-image/. \
  /data/eagler-1.12-next/
docker rm eaglerx-upgrade-template
```

Оставьте контейнер-шаблон незапущенным. [docker cp](https://docs.docker.com/reference/cli/docker/container/cp/) поддерживает копирование из остановленных контейнеров. После копирования шаблона перенесите постоянные данные из старого каталога:

| Данные | Способ переноса |
|------|----------|
| `server-1.12/<level-name>` и каталоги Nether и End | Скопируйте миры полностью и согласуйте `level-name` с именами каталогов |
| `server-data/` | Скопируйте весь репозиторий плагинов, файлы-маркеры и старые каталоги миров |
| Файлы Paper `*.properties`, `*.yml` и `*.json` | Объедините настройки с новым шаблоном; сохраните операторов, белые списки, блокировки и кэши игроков |
| Настройки Bungee, базы аутентификации и кэши скинов | Переносите настройки и базы отдельно; проверьте пользовательские данные в корне и каталогах плагинов |
| Изменённый фронтенд, плагины и параметры запуска | Объедините нужные изменения; JAR сервера, скрипты и ресурсы панели возьмите из целевого образа |

Точка входа заново создаёт ссылки `server/`, `web/` и `plugins` Paper. Скопируйте внешние данные в новый каталог хоста и подключите его в новом контейнере по прежнему внутреннему пути. Старый корень оставьте старому контейнеру. Включите данные других версий и пользовательских миров в список переноса.

**Шаг 3: Запустите новый контейнер.** В [команде быстрого запуска](#2-запустите-paper-1122) замените имя на `eaglerx-1.12-next`, каталог хоста на `/data/eagler-1.12-next`, образ на целевую версию. Сохраните прежние версию игры, пароль, общедоступный адрес и сопоставления портов.

**Шаг 4: Проверьте перенос.** Убедитесь, что Paper готов, игроки входят, миры целы, плагины загружаются, белые списки и карты работают. Затем определите срок хранения прежнего контейнера, образа и копий.

### Откат и восстановление

Если старый контейнер и каталог сохранены, остановите новый контейнер и запустите старый:

```bash
docker stop -t 45 eaglerx-1.12-next
docker start eaglerx-1.12
```

Откат возвращает состояние, сохранённое в старом каталоге. Сохраните данные, созданные во время работы нового контейнера, для последующего восстановления. Распакуйте архив в новый каталог, подключите извлечённый `eagler-1.12` как полный рабочий каталог и используйте версию образа и параметры запуска, соответствующие копии.

## Эксплуатация и устранение неполадок

Эти команды используют стандартное имя контейнера:

```bash
# Container health and entrypoint / HTTP logs
docker inspect --format '{{.State.Status}} / {{.State.Health.Status}}' eaglerx-1.12
docker logs --tail 100 eaglerx-1.12

# Paper console output in the managed tmux session
docker exec -e TMUX_TMPDIR=/tmp/eaglerx-tmux eaglerx-1.12 \
  tmux capture-pane -p -t mcserver:0.1 -S -100

# Public status probe when RCON is enabled, via the host or SSH tunnel
curl -sS http://127.0.0.1:5201/api/status
```

Paper и Bungee работают в tmux. Показанная консоль Paper использует стандартную панель `mcserver:0.1`, Bungee — `mcserver:0.0`. Проверка здоровья Docker опрашивает порты 5200, 5201 и 25565. Панель дополнительно проверяет RCON для определения готовности Paper.

| Симптом | Что проверить |
|------|------------|
| Контейнер сразу завершается | Убедитесь, что `MINECRAFT_VERSION` равно `1.8` или `1.12`, и найдите конкретную ошибку в журнале |
| При запуске сообщается о неполном каталоге | Инициализируйте пустой каталог или восстановите полную копию; текущий каталог сохраните для анализа |
| Панель открыта, Paper ещё запускается | Проверьте генерацию мира и загрузку плагинов в консоли; панель обновится после готовности Paper |
| Удалённая панель недоступна | Проверьте доступ SSH-туннеля или прокси управления к `127.0.0.1:5201` на хосте |
| Быстрая ссылка неверна или HTTPS не соединяется | Проверьте `PUBLIC_GAME_URL`, общедоступный порт и WebSocket-перенаправление игрового прокси |
| `/api/status` возвращает 404 | Задайте `RCON_PASSWORD` и пересоздайте контейнер; скрипт запуска включает RCON по этому значению |
| Вход возвращает 429 | Пять неудачных попыток от одного источника в окне ошибок вызывают блокировку на 10 минут; администраторы за туннелем или прокси могут иметь общий источник |
| Изменения сохранены, прежнее поведение сохраняется | Выполните управляемый перезапуск Paper через панель и проверьте рабочее состояние |
| Dynmap возвращает 502 | Проверьте включение и завершение загрузки Dynmap, затем адрес и порт HTTP |
| Нативный поиск структур завершается ошибкой | Проверьте окружение `linux/amd64`, ошибки загрузки нативных библиотек и чтение сида |

Точка входа запускает Bungee, Paper и HTTP в указанном порядке и постоянно следит за ними. Завершение основного сервиса останавливает весь контейнер со статусом ошибки. При `SIGTERM` / `SIGINT` выполняется корректная остановка. Настройте политику перезапуска с учётом того, что выключение через панель также завершает контейнер.

## Переменные окружения

Передавайте их через `docker run -e`. Чтобы изменить переменные контейнера, пересоздайте его с прежним подключением каталога.

| Переменная | По умолчанию | Описание |
|------|--------|------|
| `MINECRAFT_VERSION` | Обязательна | `1.8` выбирает Paper 1.8.8; `1.12` выбирает Paper 1.12.2 |
| `RCON_PASSWORD` | Пусто | При заданном значении включает RCON и API; при пустом значении защищённые административные методы отключены |
| `PUBLIC_GAME_URL` | Пусто | Общедоступный HTTP(S)-адрес игры для быстрых ссылок и адресов WebSocket |
| `PERSISTENT_DATA_ROOT` | `${APP_DIR}/server-data` | Корень репозиториев плагинов и старых подключений миров; пустой каталог автоматически инициализирует репозиторий |
| `SERVER_DATA_DIR` | Пусто | Псевдоним совместимости для `PERSISTENT_DATA_ROOT`; явно заданное значение последней имеет приоритет |
| `ADMIN_AUTH_TOKEN_TTL` | `28800` | Срок действия токена администратора в секундах |
| `ADMIN_AUTH_SECRET` | Производная пароля RCON | Необязательный секрет для подписи токенов |
| `DYNMAP_HOST` / `DYNMAP_PORT` | `127.0.0.1` / `8123` | Адрес Dynmap, к которому обращается бэкенд управления |

## API управления

Для интеграции со скриптами. Все методы используют порт управления **5201**. Повседневные действия доступны через панель.

<details>
<summary>Методы, аутентификация и примеры curl</summary>

«Общедоступный» описывает требования аутентификации самого метода. Обращайтесь к порту управления через [SSH-туннель или прокси управления](#удалённое-управление-и-порты).

| Метод | Условия доступа |
|------|----------|
| `GET /api/connection-info` | Всегда доступен; возвращает настройки общедоступного игрового входа |
| `GET /api/status` | Доступен при включённом RCON; возвращает состояние Paper и связанную информацию |
| `POST /api/login` | При включённом RCON обменивает пароль администратора на токен |
| Административные JSON-методы, включая `POST /api/rcon`, `/api/config`, `/api/system` и `/api/plugins` | Тело запроса должно содержать действующий `token` |
| `POST /api/plugins/upload` | `Authorization: Bearer <token>`, необработанное содержимое JAR в теле запроса и заголовок `X-Plugin-Filename` |
| `GET /dynmap/` | Прямой прокси к Dynmap; доступ защищается каналом управления |

JSON-запросы ограничены 64 KiB и временем чтения 10 секунд. Загрузка JAR ограничена 64 MiB и общим временем чтения 30 секунд. Администраторы с общим источником туннеля или обратного прокси могут разделять одно окно блокировки входа.

```bash
# Exchange the management password for a token
curl -sS http://127.0.0.1:5201/api/login \
  -H 'Content-Type: application/json' \
  -d '{"password":"replace-with-a-strong-password"}'

# Use the returned token for a management command
curl -sS http://127.0.0.1:5201/api/rcon \
  -H 'Content-Type: application/json' \
  -d '{"command":"list","token":"TOKEN_FROM_LOGIN"}'
```

## Разработка, сборка и выпуск

### Локальные изменения и проверка

Выполняйте команды из корня репозитория с установленными Python 3 и Docker. Меняйте ресурсы панели в `web-1.8/`, затем запускайте синхронизацию для обновления `web-1.12/`. Требования к базовому образу и нативным библиотекам описаны в [решении о базовом образе](../adr/0007-retain-the-verified-runtime-base.md).

```bash
python3 script/sync_admin_assets.py
python3 script/sync_admin_assets.py --check
docker build --platform linux/amd64 -t eaglerx-local:dev .
```

Локальная проверка выпуска также требует Node.js, tmux, `agent-browser` и работающий Chrome. CI фиксирует `agent-browser@0.26.0`; шаги установки есть в [процессе публикации](../../.github/workflows/release.yml).

```bash
agent-browser doctor
./script/release_gate.sh --evidence-dir artifacts/release-gate
```

Локальные проверки охватывают синтаксис Python, регрессии сервера и плагинов, ресурсы двух версий, панель и браузерные сценарии на английском и упрощённом китайском. Браузер использует локальный Mock Admin API. Полная проверка также собирает образ и запускает обе версии Paper:

```bash
./script/release_gate.sh \
  --build --live \
  --image eaglerx-release-gate:local \
  --evidence-dir artifacts/release-gate
```

Проверка задаёт `release_ready` значение `true` в `summary.json` только после успешного прохождения всех тестов `--live`. Область проверки, форматы доказательств и права временных подключений Linux описаны в [документации release gate](../release-gate.md).

### Публикация версии

Официальные выпуски используют Git-теги `vMAJOR.MINOR` или `vMAJOR.MINOR.PATCH`. Процесс полностью проверяет один образ и публикует его в GHCR с тегами версии и SHA коммита и подтверждением происхождения сборки. Автоматическая публикация наибольшей версии обновляет `latest`. Ручной повтор обновляет только указанную версию и SHA-теги.

```bash
gh workflow run release.yml -f release_tag=v2.2.5
```

`build.sh` упрощает локальную сборку; аргумент `push` напрямую отправляет образ. Официальная публикация следует [требованию полной live-проверки](../adr/0005-require-the-live-release-gate.md) и описанному процессу тегов.

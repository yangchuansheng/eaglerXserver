## Initial baseline procedure

Execute all steps independently for Docker 1.8, Docker 1.12, Sealos 1.8, and
Sealos 1.12. Each result must record UTC execution time, operator, OS/architecture,
browser/version, release source and image digest, template/rendered configuration
identity, outcome, sanitized evidence reference, and any limitation.

1. Deploy a disposable instance with independent storage from the documented
   setup. Capture Paper Ready, the Paper `version` response, `java -version`
   inside the running image, proxy version, and loaded authentication plugin
   versions. Record the Game Entry, Quick Join Link, and WebSocket Game Address
   using redacted host aliases in public evidence.
2. Use a fresh browser profile and stable test player name. Follow the bundled
   client screens, record the proxy-authentication prompt and any `/eagler`
   prerequisite, then record the actual LoginSecurity registration sequence.
   Stop the scenario and record a concrete defect if the documented route fails.
3. Reconnect with the same profile/name, complete the observed login sequence,
   and compare player identity. Separately authenticate the administrator with
   the deployment's RCON credential. Record pass/fail; keep credentials private.
4. Have a second player on a genuinely different network open the documented
   route. Record both players visible in the world and admin player list. A
   second tab on the same connection covers a different test boundary.
5. Place a distinctive block pattern, carry named/countable inventory items,
   save a home, and record identity plus world/inventory observations privately.
   Save, restart Paper and the container/Pod, reconnect, and compare those facts.
6. Stop all writers consistently. For Docker, use the README's stopped full-runtime
   archive including external data roots. For Sealos, scale the StatefulSet to
   zero, wait for Pod termination, and mount its PVC in a temporary backup helper.
   Archive the complete `/eaglerx-data` tree and retain the rendered StatefulSet,
   ConfigMap and required secret configuration privately. Copy the archive off
   the active volume and record its checksum in private evidence.
7. Restore into a fresh Docker directory or fresh Sealos PVC. For the PVC, use
   a temporary helper to extract the archive before starting the new workload;
   retain ownership, symlink targets, mount paths and matching source image/template.
   Remove the helper before mounting the restored volume in the workload.
   Reconnect and verify login, world blocks, inventory, homes, plugins, operators,
   whitelist and configuration. Record each outcome; preserve the recovery copy.
8. Execute the planned release pair below using a separate restored copy. Follow
   the Docker runtime-file migration or Sealos init-refresh behavior documented
   in the compatibility reference. Keep the Game Version and original recovery
   data unchanged. Recheck all identity/world/inventory facts on the target.
9. Stop the upgraded copy and start the retained source instance or a fresh
   source restoration with its original image/template. Verify login, world,
   inventory and configuration again. Retain target-period writes separately.
10. Publish concise sanitized outcomes and limitations, using test-player aliases
    and redacted screenshots. Remove only the disposable resources created for
    the run after the evidence and independent recovery copy are retained.

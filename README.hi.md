# EaglercraftX Server

ऐसा Minecraft सर्वर चलाएँ जिससे खिलाड़ी ब्राउज़र के ज़रिए जुड़ सकें। इसमें स्थायी स्टोरेज और खिलाड़ियों, दुनियाओं तथा प्लगइन को सँभालने के लिए एडमिन पैनल है। Docker इमेज में EaglercraftX 1.8 / 1.12 क्लाइंट और Paper 1.8.8 / 1.12.2 सर्वर शामिल हैं; शुरू करते समय गेम का संस्करण चुनें।

## त्वरित शुरुआत

### 1. होस्ट तैयार करें

- **होस्ट**: Docker इंस्टॉल करें और स्थायी स्टोरेज तैयार रखें। उदाहरणों में Linux पाथ हैं। प्रकाशित इमेज AMD64 के लिए हैं; ARM64 एमुलेशन और नेटिव लाइब्रेरी की अनुकूलता अलग से जाँचें। [आर्किटेक्चर निर्णय](docs/adr/0006-publish-linux-amd64-only.md) देखें।
- **मेमोरी**: Paper और Bungee, दोनों अलग-अलग `-Xms256M -Xmx256M` इस्तेमाल करते हैं। JVM के हीप से बाहर की मेमोरी, दुनिया बनाने और प्लगइन के लिए अतिरिक्त जगह रखें। हीप का आकार बदलने के लिए संबंधित रनटाइम डायरेक्टरी में `run.sh` संपादित करें।
- **EULA**: स्टार्टअप स्क्रिप्ट `eula=true` लिखती है। डिप्लॉय करने से पहले [Minecraft EULA](https://www.minecraft.net/en-us/eula) पढ़कर स्वीकार करें।

### 2. Paper 1.12.2 शुरू करें

ये कमांड सर्वर पर चलाएँ। `YOUR_SERVER` की जगह खिलाड़ियों की पहुँच वाला IP पता या डोमेन और `replace-with-a-strong-password` की जगह अपना एडमिन पासवर्ड लिखें।

यह उदाहरण होस्ट की `/data/eagler-1.12` डायरेक्टरी को कंटेनर के अंदर `/eaglerX-1.8-server` पर माउंट करता है और **पूरी रनटाइम डायरेक्टरी** को स्थायी रखता है: दुनियाएँ, प्लगइन, कॉन्फ़िगरेशन और फ़्रंटएंड फ़ाइलें। खाली डायरेक्टरी पहली बार अपने आप तैयार होती है। मौजूदा डायरेक्टरी अधूरी होने पर स्टार्टअप उसकी सामग्री सुरक्षित रखकर बंद हो जाता है। मौजूदा डिप्लॉयमेंट की रनटाइम फ़ाइलें स्थानांतरित करने के लिए [बैकअप, अपग्रेड और रोलबैक](#बैकअप-अपग्रेड-और-रोलबैक) का पालन करें।

```bash
docker pull --platform linux/amd64 ghcr.io/yangchuansheng/eaglerx1.8server:2.2.5

docker run -d \
  --name eaglerx-1.12 \
  --platform linux/amd64 \
  --stop-timeout 45 \
  -p 5200:5200 \
  -p 127.0.0.1:5201:5201 \
  -v /data/eagler-1.12:/eaglerX-1.8-server \
  -e MINECRAFT_VERSION=1.12 \
  -e 'RCON_PASSWORD=replace-with-a-strong-password' \
  -e 'PUBLIC_GAME_URL=http://YOUR_SERVER:5200' \
  ghcr.io/yangchuansheng/eaglerx1.8server:2.2.5
```

### 3. एडमिन पैनल खोलें और तैयार स्थिति जाँचें

| प्रवेश | पता | इस्तेमाल |
|------|------|----------|
| गेम | `http://YOUR_SERVER:5200/` | खिलाड़ियों के साथ साझा करें और [जुड़ने के निर्देश](#सर्वर-से-जुड़ना) पढ़ें |
| एडमिन पैनल | `http://127.0.0.1:5201/admin` | होस्ट से खोलें और स्टार्टअप पर तय किए गए एडमिन पासवर्ड से लॉगिन करें |

पहली दुनिया बनने में कुछ मिनट लग सकते हैं। पैनल में **Paper is ready** दिखने पर स्टार्टअप पूरा है। लंबा इंतज़ार या त्रुटि होने पर [संचालन और समस्या समाधान](#संचालन-और-समस्या-समाधान) देखें।

### रिमोट प्रबंधन और पोर्ट

रिमोट सर्वर सँभालने के लिए अपने कंप्यूटर से SSH टनल खोलें। `user@YOUR_SERVER` की जगह सर्वर का SSH लॉगिन पता लिखें:

```bash
ssh -N -L 5201:127.0.0.1:5201 user@YOUR_SERVER
```

टनल खुली रखें और `http://127.0.0.1:5201/admin` खोलें। होस्ट के `127.0.0.1:5201` को अपस्ट्रीम बनाकर HTTPS रिवर्स प्रॉक्सी भी इस्तेमाल कर सकते हैं। VPN के प्रबंधन प्रवेश को इस लूपबैक पते पर ट्रैफ़िक भेजने में सक्षम होना चाहिए।

| पोर्ट | उपयोग | पहुँच |
|------|------|----------|
| 5200 | HTTP गेम पेज, सार्वजनिक स्टैटिक फ़ाइलें और WebSocket गेम कनेक्शन | खिलाड़ियों के लिए खोलें |
| 5201 | एडमिन पैनल, वैकल्पिक HTTP सेवा और Dynmap प्रॉक्सी | होस्ट पर `127.0.0.1` से बाइंड करें |
| 25565 | Paper | कंटेनर के अंदर localhost |
| 25575 | RCON | कंटेनर के अंदर localhost |

### कस्टम डोमेन, HTTPS और गेम URL

`PUBLIC_GAME_URL` में **खिलाड़ियों द्वारा वास्तव में इस्तेमाल किया जाने वाला HTTP(S) गेम URL** डालें। पैनल इससे तुरंत जुड़ने के लिंक और `ws` / `wss` पते बनाता है। खाली छोड़ने पर पैनल के मौजूदा होस्टनाम और पोर्ट 5200 से HTTP URL बनता है (`http://主机名:5200/`)। SSH टनल, अलग एडमिन डोमेन या कस्टम गेम पोर्ट के साथ इसे स्पष्ट रूप से तय करें।

HTTPS गेम प्रवेश के लिए DNS, प्रमाणपत्र और **5200** पर HTTP तथा WebSocket फ़ॉरवर्डिंग चाहिए। एडमिन प्रॉक्सी को **5201** पर भेजें। `PUBLIC_GAME_URL` केवल कनेक्शन पते बनाता है; प्रॉक्सी और प्रमाणपत्र अपने डिप्लॉयमेंट में कॉन्फ़िगर करें।

### 1.8 चुनना या दोनों संस्करण चलाना

`2.2.5` इमेज का रिलीज़ संस्करण है। `MINECRAFT_VERSION=1.8` से Paper 1.8.8 और `1.12` से Paper 1.12.2 चुना जाता है। हर कंटेनर एक समय में एक गेम संस्करण चलाता है और अलग रनटाइम डायरेक्टरी रखता है।

1.8 चलाने के लिए त्वरित शुरुआत की कमांड में ये पैरामीटर बदलें:

| पैरामीटर | केवल 1.8 चलाएँ | 1.12 के साथ 1.8 चलाएँ |
|------|-------------|---------------------|
| कंटेनर का नाम | `--name eaglerx-1.8` | पिछले कॉलम जैसा |
| गेम का संस्करण | `-e MINECRAFT_VERSION=1.8` | पिछले कॉलम जैसा |
| पूरी रनटाइम डायरेक्टरी का माउंट | `-v /data/eagler-1.8:/eaglerX-1.8-server` | पिछले कॉलम जैसा |
| गेम पोर्ट | `-p 5200:5200` | `-p 5300:5200` |
| एडमिन पोर्ट | `-p 127.0.0.1:5201:5201` | `-p 127.0.0.1:5301:5201` |
| सार्वजनिक गेम URL | `http://YOUR_SERVER:5200` | `http://YOUR_SERVER:5300` |

`PUBLIC_GAME_URL` को उस इंस्टेंस के URL पर सेट करें। दूसरे इंस्टेंस के रिमोट प्रबंधन के लिए `ssh -N -L 5301:127.0.0.1:5301 user@YOUR_SERVER` चलाएँ और `http://127.0.0.1:5301/admin` खोलें।

## सर्वर से जुड़ना

1. गेम URL खोलें या सर्वर मालिक द्वारा पैनल के Overview पेज से साझा किया गया तुरंत जुड़ने का लिंक इस्तेमाल करें। 1.12 क्लाइंट में शुरुआती सर्वर सूची खाली होती है; Multiplayer में `ws://YOUR_SERVER:5200/` जोड़ें या HTTPS प्रवेश के लिए संबंधित `wss://` पता इस्तेमाल करें।
2. पहली बार LoginSecurity के निर्देश पर `/register <password>` दर्ज करें। अगली बार `/login <password>` इस्तेमाल करें। डिफ़ॉल्ट रूप से पंजीकरण अनिवार्य है, पासवर्ड कम से कम 6 कैरेक्टर का हो और लॉगिन की समय सीमा 30 सेकंड है।
3. LoginSecurity खिलाड़ियों के खातों के पासवर्ड सँभालता है। एडमिन पैनल सर्वर मालिक का `RCON_PASSWORD` इस्तेमाल करता है।

SimpleHomes में `/sethome <name>`, `/home <name>` और `/homes` हैं। SimpleTpa में `/tpa <player>`, `/tpaccept` और `/tpdeny` हैं। अनुमतियाँ और व्यवहार प्लगइन के मौजूदा कॉन्फ़िगरेशन पर निर्भर हैं।

## एडमिन पैनल और प्लगइन

### लॉगिन और बदलाव लागू करना

`RCON_PASSWORD` सेट करने से RCON और एडमिन API सक्रिय होते हैं। लॉगिन के बाद ब्राउज़र मौजूदा सेशन में एडमिन टोकन रखता है; उसकी डिफ़ॉल्ट वैधता 8 घंटे है। लॉगआउट स्थानीय टोकन मिटाता है। इंटरफ़ेस डिफ़ॉल्ट रूप से अंग्रेज़ी में है, सरलीकृत चीनी का समर्थन करता है और साइट के लिए चुनी गई भाषा याद रखता है।

Paper के शुरू होते समय भी लॉगिन कर सकते हैं। गेम नियंत्रण Paper तैयार होने पर उपलब्ध होंगे।

| कार्रवाई | कब लागू होगी |
|------|----------|
| मौसम, समय, गेम नियम, खिलाड़ी और व्हाइटलिस्ट कमांड | चल रहे Paper को भेजी जाती हैं; कंसोल का जवाब देखें |
| MOTD, खिलाड़ी सीमा, दृश्य दूरी और PVP जैसे कॉन्फ़िगरेशन | `server.properties` में लिखे जाते हैं और Paper रीस्टार्ट के बाद लागू होते हैं |
| प्लगइन अपलोड, सक्रिय करना, निष्क्रिय करना और हटाना | रिपॉज़िटरी में सहेजे जाते हैं और Paper रीस्टार्ट के बाद लागू होते हैं |
| पैनल से Minecraft रीस्टार्ट | Paper का नियंत्रित रीस्टार्ट होता है; Bungee और पैनल चलते रहते हैं |
| पैनल से बंद करना या कंसोल में `stop` | Paper बंद होता है और पूरा कंटेनर बंद होने लगता है |

Dynmap पैनल की `/dynmap/` प्रॉक्सी से उपलब्ध है। नेटिव स्ट्रक्चर खोज इमेज में शामिल cubiomes घटक इस्तेमाल करती है। संरचनाएँ और अनुमानित स्पॉन स्थान दुनिया के सीड से निकाले जाते हैं; खिलाड़ी की स्थिति Dynmap या खिलाड़ी के सेव डेटा से मिलती है। बाहरी Seed Map खोलने पर गंतव्य URL में दुनिया का सीड शामिल होता है।

### प्लगइन रिपॉज़िटरी और डेटा

सक्रिय संस्करण की रिपॉज़िटरी `server-data/plugins-1.8` या `server-data/plugins-1.12` पर है। `enabled/` डायरेक्टरी में सक्रिय पैकेज और प्लगइन डेटा, जबकि `disabled/` में निष्क्रिय पैकेज रहते हैं। Paper का `plugins` पाथ सक्रिय रिपॉज़िटरी की `enabled/` डायरेक्टरी की ओर जाता है।

पहली शुरुआत में शामिल प्लगइन पैकेज और डेटा आयात होते हैं। बाद की शुरुआत मौजूदा स्थिति, मैन्युअल बदलाव, निष्क्रिय पैकेज और हटाने के परिणाम सुरक्षित रखती है। पूरी रनटाइम डायरेक्टरी का माउंट यह सारा डेटा स्थायी रखता है।

पैनल सक्रिय गेम संस्करण, फ़ाइल आकार, संशोधन समय, अगली शुरुआत की स्थिति और लंबित रीस्टार्ट दिखाता है:

- अपलोड JAR फ़ाइल हो और आर्काइव की जड़ में `plugin.yml` शामिल हो। नाम छोटे अक्षरों वाले `.jar` पर समाप्त हो और आकार अधिकतम **64 MiB** हो। दोहराया नाम टकराव लौटाता है।
- प्लगइन अपलोड, सक्रिय, निष्क्रिय या हटाने के बाद नया सेट लोड करने के लिए पैनल से रीस्टार्ट करें। लोड हो चुका कोड Paper रुकने तक सक्रिय रहता है।
- प्लगइन हटाने पर JAR मिटता है और कॉन्फ़िगरेशन तथा डेटाबेस सुरक्षित रहते हैं। उसी डेटा डायरेक्टरी का उपयोग करने वाला अनुकूल प्लगइन दोबारा इंस्टॉल करके डेटा फिर इस्तेमाल कर सकता है।
- JAR, Paper प्रक्रिया की अनुमतियों से चलते हैं। भरोसेमंद स्रोत चुनें, इंस्टॉल करने से पहले पैकेज की समीक्षा और स्कैन करें तथा बैकअप लें।

<details>
<summary>मौजूदा दुनियाएँ और अलग डेटा डायरेक्टरी (पुरानी व्यवस्था का समर्थन)</summary>

`PERSISTENT_DATA_ROOT` प्लगइन रिपॉज़िटरी और पुराने विश्व माउंट के लिए साझा रूट तय करता है। `SERVER_DATA_DIR` उसका संगतता उपनाम है। डिफ़ॉल्ट डिप्लॉयमेंट पूरी रनटाइम डायरेक्टरी माउंट करता है।

**खाली अलग डेटा डायरेक्टरी केवल प्लगइन रिपॉज़िटरी आरंभ करती है।** दुनिया के प्रतीकात्मक लिंक बनाने के लिए संबंधित दुनिया उस डेटा रूट में पहले से होनी चाहिए। नई दुनियाएँ संस्करण की `server-版本/` डायरेक्टरी में रहती हैं और पूरे रनटाइम माउंट से सुरक्षित रहती हैं।

मौजूदा दुनियाएँ स्थानांतरित करने से पहले सर्वर रोकें और बैकअप लें, फिर `<level-name>`, `<level-name>_nether` और `<level-name>_the_end` डायरेक्टरी तैयार करें। डिफ़ॉल्ट नाम `world`, `world_nether` और `world_the_end` हैं। एंट्रीपॉइंट इन नामों को वैकल्पिक रूप से इस्तेमाल कर सकता है और सर्वर पाथ पर मौजूद असली दुनिया डायरेक्टरी सुरक्षित रखता है। हर संस्करण के लिए अलग डेटा रूट रखें और शुरुआत के बाद हर लिंक का वास्तविक लक्ष्य जाँचें।

## बैकअप, अपग्रेड और रोलबैक

### सर्वर रोककर बैकअप लें

ये कमांड त्वरित शुरुआत वाले कंटेनर और माउंट का उपयोग करते हैं। बैकअप में दुनियाएँ, खिलाड़ी की स्थिति, प्लगइन डेटा, कॉन्फ़िगरेशन, प्रमाणीकरण डेटाबेस और एडमिन पासवर्ड होते हैं। इसे सीमित पहुँच वाली डायरेक्टरी में रखें।

```bash
docker stop -t 45 eaglerx-1.12
sudo install -d -m 700 /data/backups
sudo tar -czf "/data/backups/eagler-1.12-$(date +%Y%m%d-%H%M%S).tar.gz" \
  -C /data eagler-1.12
```

नियमित बैकअप पूरा होने पर `docker start eaglerx-1.12` चलाएँ। अपग्रेड के दौरान पुराना कंटेनर रुका रहने दें। बाहरी `PERSISTENT_DATA_ROOT` इस्तेमाल हो तो उस रूट का भी बैकअप लें; tar डिफ़ॉल्ट रूप से प्रतीकात्मक लिंक को ही सुरक्षित रखता है।

रुकने का संकेत मिलने पर एंट्रीपॉइंट Paper को अधिकतम 30 सेकंड और उसके बाद Bungee को अधिकतम 10 सेकंड देता है। उदाहरण में Docker की 45 सेकंड की स्टॉप सीमा इस क्रम के लिए समय देती है। [Docker के रुकने का व्यवहार](https://docs.docker.com/reference/cli/docker/container/stop/) देखें।

### नई डायरेक्टरी में अपग्रेड तैयार करें

**पूरी रनटाइम डायरेक्टरी केवल पहली शुरुआत में इमेज से तैयार होती है।** इमेज बदलने के बाद भी मौजूदा माउंट सर्वर, फ़्रंटएंड और Python बैकएंड की फ़ाइलें देता रहता है। अपग्रेड के लिए रनटाइम फ़ाइलें स्पष्ट रूप से बदलें और स्थायी स्थिति स्थानांतरित करें।

**चरण 1: रोकें और बैकअप लें।** पुराना कंटेनर, रनटाइम डायरेक्टरी और इमेज संस्करण सुरक्षित रखें।

**चरण 2: नई रनटाइम डायरेक्टरी तैयार करें।** लक्षित इमेज से पूरा टेम्पलेट कॉपी करें। इस उदाहरण में `2.2.5` है; टेम्पलेट कंटेनर का ऐसा नाम और डायरेक्टरी चुनें जो अभी उपयोग में न हों:

```bash
docker pull --platform linux/amd64 ghcr.io/yangchuansheng/eaglerx1.8server:2.2.5
docker create --name eaglerx-upgrade-template --platform linux/amd64 \
  ghcr.io/yangchuansheng/eaglerx1.8server:2.2.5
sudo mkdir /data/eagler-1.12-next
sudo docker cp eaglerx-upgrade-template:/opt/eaglerX-1.8-server-image/. \
  /data/eagler-1.12-next/
docker rm eaglerx-upgrade-template
```

टेम्पलेट कंटेनर को बिना शुरू किए रखें। [docker cp](https://docs.docker.com/reference/cli/docker/container/cp/) रुके कंटेनर से फ़ाइलें कॉपी कर सकता है। टेम्पलेट कॉपी होने पर पुरानी डायरेक्टरी की स्थायी स्थिति स्थानांतरित करें:

| डेटा | स्थानांतरण का तरीका |
|------|----------|
| `server-1.12/<level-name>` तथा उसके Nether और End डायरेक्टरी | पूरी दुनियाएँ कॉपी करें और `level-name` को डायरेक्टरी के नामों से मेल खाते रखें |
| `server-data/` | पूरी प्लगइन रिपॉज़िटरी, मार्कर फ़ाइलें और पुरानी दुनिया डायरेक्टरी कॉपी करें |
| Paper की `*.properties`, `*.yml` और `*.json` फ़ाइलें | नए टेम्पलेट से सेटिंग मिलाएँ; ऑपरेटर, व्हाइटलिस्ट, प्रतिबंध और खिलाड़ी कैश सुरक्षित रखें |
| Bungee कॉन्फ़िगरेशन, प्रमाणीकरण डेटाबेस और स्किन कैश | सेटिंग और डेटाबेस अलग-अलग स्थानांतरित करें; रूट और प्लगइन डायरेक्टरी में कस्टम डेटा जाँचें |
| कस्टम फ़्रंटएंड, प्लगइन और शुरू करने के विकल्प | आवश्यक बदलाव मिलाएँ; सर्वर JAR, स्क्रिप्ट और एडमिन संसाधन लक्षित इमेज से लें |

एंट्रीपॉइंट `server/`, `web/` और Paper के `plugins` प्रतीकात्मक लिंक दोबारा बनाता है। बाहरी डेटा को नई होस्ट डायरेक्टरी में कॉपी करें, फिर नए कंटेनर में उसके पुराने आंतरिक पाथ पर माउंट करें। पुराना डेटा रूट पुराने कंटेनर के लिए रखें। दूसरे संस्करणों और कस्टम दुनियाओं का डेटा भी स्थानांतरण सूची में शामिल करें।

**चरण 3: नया कंटेनर शुरू करें।** [त्वरित शुरुआत कमांड](#2-paper-1122-शुरू-करें) में नाम `eaglerx-1.12-next`, होस्ट डायरेक्टरी `/data/eagler-1.12-next` और इमेज का लक्षित संस्करण रखें। पुराना गेम संस्करण, पासवर्ड, सार्वजनिक URL और पोर्ट मैपिंग सुरक्षित रखें।

**चरण 4: स्थानांतरण सत्यापित करें।** Paper तैयार हो, खिलाड़ी जुड़ सकें, पुरानी दुनियाएँ सही हों, प्लगइन लोड हों और व्हाइटलिस्ट तथा नक्शे काम करें। फिर पुराने कंटेनर, इमेज और बैकअप को रखने की अवधि तय करें।

### रोलबैक और पुनर्स्थापना

पुराना कंटेनर और डायरेक्टरी सुरक्षित हों तो नया कंटेनर रोकें और पुराना शुरू करें:

```bash
docker stop -t 45 eaglerx-1.12-next
docker start eaglerx-1.12
```

रोलबैक पुरानी डायरेक्टरी में सहेजी गई स्थिति लौटाता है। नए कंटेनर के चलते समय बने डेटा को बाद की पुनर्स्थापना के लिए सुरक्षित रखें। संपीड़ित बैकअप नई डायरेक्टरी में निकालें, निकली हुई `eagler-1.12` डायरेक्टरी को पूरी रनटाइम डायरेक्टरी की तरह माउंट करें और उस बैकअप की इमेज तथा शुरू करने के विकल्प इस्तेमाल करें।

## संचालन और समस्या समाधान

ये कमांड कंटेनर का डिफ़ॉल्ट नाम इस्तेमाल करते हैं:

```bash
# Container health and entrypoint / HTTP logs
docker inspect --format '{{.State.Status}} / {{.State.Health.Status}}' eaglerx-1.12
docker logs --tail 100 eaglerx-1.12

# Paper console output in the managed tmux session
docker exec -e TMUX_TMPDIR=/tmp/eaglerx-tmux eaglerx-1.12 \
  tmux capture-pane -p -t mcserver:0.1 -S -100

# Public status probe when RCON is enabled, via the host or SSH tunnel
curl -sS http://127.0.0.1:5201/api/status
```

Paper और Bungee tmux में चलते हैं। ऊपर का Paper कंसोल डिफ़ॉल्ट पेन `mcserver:0.1` और Bungee `mcserver:0.0` इस्तेमाल करता है। Docker हेल्थ जाँच पोर्ट 5200, 5201 और 25565 देखती है। पैनल Paper की तैयार स्थिति के लिए RCON भी जाँचता है।

| लक्षण | क्या जाँचें |
|------|------------|
| कंटेनर तुरंत बंद हो जाता है | जाँचें कि `MINECRAFT_VERSION` का मान `1.8` या `1.12` हो और लॉग में सटीक त्रुटि देखें |
| शुरुआत में रनटाइम डायरेक्टरी अधूरी बताई जाती है | खाली डायरेक्टरी तैयार करें या पूरा बैकअप लौटाएँ; मौजूदा डायरेक्टरी जाँच के लिए सुरक्षित रखें |
| पैनल खुलता है लेकिन Paper अभी शुरू हो रहा है | कंसोल में दुनिया बनने और प्लगइन लोड होने की प्रगति देखें; Paper तैयार होने पर पैनल अपडेट होगा |
| रिमोट एडमिन पैनल उपलब्ध नहीं है | जाँचें कि SSH टनल या एडमिन प्रॉक्सी होस्ट के `127.0.0.1:5201` तक पहुँच सके |
| त्वरित लिंक गलत है या HTTPS कनेक्शन विफल है | `PUBLIC_GAME_URL`, सार्वजनिक पोर्ट और गेम प्रॉक्सी की WebSocket फ़ॉरवर्डिंग जाँचें |
| `/api/status` से 404 मिलता है | `RCON_PASSWORD` सेट करके कंटेनर दोबारा बनाएँ; स्टार्टअप स्क्रिप्ट इससे RCON सक्रिय करती है |
| लॉगिन से 429 मिलता है | विफलता अवधि में एक स्रोत की पाँच असफल कोशिशें 10 मिनट का लॉक लगाती हैं; टनल या प्रॉक्सी के पीछे एडमिन एक स्रोत साझा कर सकते हैं |
| बदलाव सहेजे गए हैं पर पुराना व्यवहार रहता है | पैनल से Paper का नियंत्रित रीस्टार्ट करें और चलती स्थिति जाँचें |
| Dynmap से 502 मिलता है | उसके सक्रिय और पूरी तरह लोड होने की जाँच करें, फिर HTTP सुनने का पता और पोर्ट देखें |
| नेटिव स्ट्रक्चर खोज विफल है | `linux/amd64` रनटाइम वातावरण, नेटिव लाइब्रेरी लोड त्रुटियाँ और दुनिया के सीड की प्राप्ति जाँचें |

एंट्रीपॉइंट क्रम से Bungee, Paper और HTTP शुरू करके लगातार निगरानी करता है। मुख्य सेवा बंद होने पर पूरा कंटेनर रुकता है और विफलता स्थिति लौटती है। `SIGTERM` / `SIGINT` मिलने पर व्यवस्थित रूप से बंद किया जाता है। रीस्टार्ट नीति तय करते समय ध्यान रखें कि पैनल से बंद करने पर कंटेनर भी समाप्त होता है।

## एनवायरनमेंट वेरिएबल

इन्हें `docker run -e` से दें। कंटेनर के एनवायरनमेंट वेरिएबल बदलने के लिए मौजूदा माउंट से कंटेनर दोबारा बनाएँ।

| वेरिएबल | डिफ़ॉल्ट | विवरण |
|------|--------|------|
| `MINECRAFT_VERSION` | अनिवार्य | `1.8` Paper 1.8.8 और `1.12` Paper 1.12.2 चुनता है |
| `RCON_PASSWORD` | खाली | सेट होने पर RCON और API सक्रिय; खाली होने पर प्रमाणीकरण वाले एडमिन एंडपॉइंट बंद |
| `PUBLIC_GAME_URL` | खाली | त्वरित लिंक और WebSocket पते बनाने वाला सार्वजनिक HTTP(S) गेम URL |
| `PERSISTENT_DATA_ROOT` | `${APP_DIR}/server-data` | प्लगइन रिपॉज़िटरी और मौजूदा दुनिया के पुराने माउंट का रूट; खाली डायरेक्टरी रिपॉज़िटरी अपने आप तैयार करती है |
| `SERVER_DATA_DIR` | खाली | `PERSISTENT_DATA_ROOT` का संगतता उपनाम; बाद वाले का स्पष्ट मान प्राथमिक है |
| `ADMIN_AUTH_TOKEN_TTL` | `28800` | एडमिन टोकन की वैधता, सेकंड में |
| `ADMIN_AUTH_SECRET` | RCON पासवर्ड से निकाला गया | टोकन साइन करने का वैकल्पिक सीक्रेट |
| `DYNMAP_HOST` / `DYNMAP_PORT` | `127.0.0.1` / `8123` | एडमिन बैकएंड द्वारा इस्तेमाल Dynmap अपस्ट्रीम पता |

<details>
<summary>एंडपॉइंट, प्रमाणीकरण और curl उदाहरण</summary>

“सार्वजनिक” एंडपॉइंट की अपनी प्रमाणीकरण शर्त बताता है। एडमिन पोर्ट पर [SSH टनल या एडमिन प्रॉक्सी](#रिमोट-प्रबंधन-और-पोर्ट) से पहुँचें।

| एंडपॉइंट | पहुँच की शर्त |
|------|----------|
| `GET /api/connection-info` | हमेशा उपलब्ध; सार्वजनिक गेम प्रवेश का कॉन्फ़िगरेशन लौटाता है |
| `GET /api/status` | RCON सक्रिय होने पर उपलब्ध; Paper की स्थिति और संबंधित जानकारी देता है |
| `POST /api/login` | RCON सक्रिय होने पर एडमिन पासवर्ड के बदले टोकन देता है |
| `POST /api/rcon`, `/api/config`, `/api/system` और `/api/plugins` जैसे JSON एडमिन एंडपॉइंट | अनुरोध बॉडी में वैध `token` होना चाहिए |
| `POST /api/plugins/upload` | `Authorization: Bearer <token>`, मूल JAR अनुरोध बॉडी और `X-Plugin-Filename` हेडर |
| `GET /dynmap/` | सीधे Dynmap को प्रॉक्सी करता है; प्रबंधन कनेक्शन पहुँच की सुरक्षा देता है |

JSON अनुरोध बॉडी की सीमा 64 KiB और पढ़ने की सीमा 10 सेकंड है। मूल JAR अपलोड की सीमा 64 MiB और कुल पढ़ने का समय 30 सेकंड है। एक ही टनल या रिवर्स प्रॉक्सी स्रोत साझा करने वाले एडमिन लॉगिन लॉक की अवधि भी साझा कर सकते हैं।

```bash
# Exchange the management password for a token
curl -sS http://127.0.0.1:5201/api/login \
  -H 'Content-Type: application/json' \
  -d '{"password":"replace-with-a-strong-password"}'

# Use the returned token for a management command
curl -sS http://127.0.0.1:5201/api/rcon \
  -H 'Content-Type: application/json' \
  -d '{"command":"list","token":"TOKEN_FROM_LOGIN"}'
```

## डेवलपमेंट, बिल्ड और रिलीज़

### स्थानीय बदलाव और सत्यापन

Python 3 और Docker इंस्टॉल करके रिपॉज़िटरी रूट से ये कमांड चलाएँ। एडमिन संसाधन `web-1.8/` में बदलें और सिंक स्क्रिप्ट से `web-1.12/` अपडेट करें। बेस इमेज और नेटिव लाइब्रेरी की जरूरतों के लिए [रनटाइम बेस इमेज निर्णय](docs/adr/0007-retain-the-verified-runtime-base.md) देखें।

```bash
python3 script/sync_admin_assets.py
python3 script/sync_admin_assets.py --check
docker build --platform linux/amd64 -t eaglerx-local:dev .
```

स्थानीय रिलीज़ जाँच के लिए Node.js, tmux, `agent-browser` और काम करने वाला Chrome भी चाहिए। CI में `agent-browser@0.26.0` तय है; इंस्टॉलेशन के चरण [रिलीज़ वर्कफ़्लो](.github/workflows/release.yml) में हैं।

```bash
agent-browser doctor
./script/release_gate.sh --evidence-dir artifacts/release-gate
```

स्थानीय जाँच Python सिंटैक्स, सर्वर और प्लगइन रिग्रेशन, दोनों संस्करणों के संसाधन, एडमिन संसाधन और अंग्रेज़ी व सरलीकृत चीनी ब्राउज़र प्रक्रियाएँ देखती है। ब्राउज़र जाँच स्थानीय Mock Admin API इस्तेमाल करती है। पूरा रिलीज़ सत्यापन इमेज बनाता है और दोनों Paper संस्करण भी चलाता है:

```bash
./script/release_gate.sh \
  --build --live \
  --image eaglerx-release-gate:local \
  --evidence-dir artifacts/release-gate
```

सभी `--live` जाँच सफल होने पर ही प्रक्रिया `summary.json` में `release_ready` को `true` करती है। कवरेज, साक्ष्य प्रारूप और Linux अस्थायी माउंट अनुमतियों के लिए [रिलीज़ जाँच दस्तावेज़](docs/release-gate.md) देखें।

### रिलीज़ प्रकाशित करना

आधिकारिक रिलीज़ `vMAJOR.MINOR` या `vMAJOR.MINOR.PATCH` Git टैग इस्तेमाल करती हैं। वर्कफ़्लो एक ही इमेज की पूरी जाँच करके उसे संस्करण और कमिट SHA टैग तथा बिल्ड उत्पत्ति प्रमाणन के साथ GHCR पर प्रकाशित करता है। सबसे ऊँचे संस्करण की स्वचालित रिलीज़ `latest` अपडेट करती है। मैन्युअल दोहराव केवल तय संस्करण और SHA टैग अपडेट करता है।

```bash
gh workflow run release.yml -f release_tag=v2.2.5
```

`build.sh` स्थानीय बिल्ड को एक साथ चलाता है; उसका `push` तर्क इमेज सीधे पुश करता है। आधिकारिक वितरण [पूरी live gate जाँच की शर्त](docs/adr/0005-require-the-live-release-gate.md) और ऊपर की टैग प्रक्रिया का पालन करता है।
